# Каталог HTTP-эндпоинтов

Все маршруты — **серверный рендеринг** (Thymeleaf-шаблоны), без REST-JSON
(кроме аякс-реакций). UI на русском. BASE = `http://localhost:8080`.

> Примечание: POST-запросы требуют **CSRF**. Анонимный POST → редирект на
> `/login`; авторизованный без CSRF → `403`.

## RPG: листы персонажей, списки и ячейки заклинаний (релиз 3.1.0)

Все маршруты под `/rpg/games/{gameId}`. POST требует CSRF и права
владельца листа или ведущего игры.

| Метод | URL | Описание | Вид |
|-------|-----|----------|-----|
| GET | `/apply` | Форма заявки/нового листа | `rpg/apply` |
| POST | `/apply` | Сохранение заявки и листа (`attributes[i].listJson` для списков) | редирект на игру |
| GET | `/npc/new` | Форма нового NPC | `rpg/apply` |
| POST | `/npc` | Создание NPC | редирект на игру |
| GET | `/characters/{sheetId}` | Просмотр листа | `rpg/character` |
| GET | `/characters/{sheetId}/edit` | Форма редактирования листа | `rpg/apply` |
| POST | `/characters/{sheetId}/edit` | Сохранение листа. Каждый блок формы (общие параметры, ячейки, деньги, инвентарь) обязан отправлять `attributes[i].key`: без ключа значение параметра отбрасывается |
| POST | `/characters/{sheetId}/spell-slots-reset` | Сброс ячеек: текущее = максимальному для всех непустых уровней | редирект на лист |
| POST | `/characters/{sheetId}/money/change` | Кнопки ± по виду монет (`kind` = `gold`\|`silver`\|`copper`, `delta` = ±N); сумма не уходит в минус | редирект на лист |
| POST | `/characters/{sheetId}/money/convert` | Обмен по курсу 1:10 (`kind`, `direction` = `up`\|`down`); одно нажатие — один обмен, некратное 10 остаётся в младшем разряде | редирект на лист |

**Деньги есть только в системе D&D.** Хранятся тремя числовыми параметрами
`money:gold`, `money:silver`, `money:copper`; в общем списке параметров листа
они не выводятся — только в разделе «Инвентарь» (`data-block="inventory"`),
подзаголовок «Деньги» (`data-block="money"`) листа и формы редактирования.
Ручной ввод суммы есть только в форме редактирования (маршрута `money/set`
нет), на странице просмотра — кнопки ± и обмен. `kind` принимает и полный ключ параметра
(`money:gold`), и короткое имя вида монет (`gold`). Количество монет не может
быть меньше нуля: в форме листа у поля `min="0"`, стрелки не уходят в минус,
отрицательное значение в `POST /characters/{sheetId}/edit` отклоняется
(`INVALID_INPUT`). Маршруты доступны владельцу листа и ведущему; для остальных
систем вызов возвращает `INVALID_INPUT`.

Кнопки обмена есть только у видов с младшим разрядом: у золота
`kind=gold&direction=up` («→ 10 см») и `kind=gold&direction=down` («← 1 зм»),
у серебра — обмен с медью, у меди кнопок обмена нет. В разметке блок обмена
стоит между строками с числом монет (`data-money-convert-row`). В форме
редактирования обмен выполняется в браузере (одно нажатие — один обмен) и
сохраняется вместе с листом; отдельного эндпоинта для формы нет.

Ручной ввод числовых параметров в D&D есть только у денег: остальные числа
(level, `hit_points`, `armor_class`, `ability:*`, `save:*`, `skill:*`,
`spell_slot_*`) в форме листа меняются стрелками, поля ввода у них нет.

**Списки правятся только в режиме редактирования.** Отдельных POST-эндпоинтов
добавления/удаления элементов списка нет: `GET /characters/{sheetId}` показывает
списки только для чтения (карточки с сворачиванием), без кнопок и модальных окон.
Правка выполняется через `POST /characters/{sheetId}/edit` с `listJson`.

### Типы списков листа

| Тип | Хранится | Правка |
|-----|----------|--------|
| «Простой список» (`SIMPLE`) | `["Факел", "Хлеб"]` | карточки + поле ввода + кнопка «+» |
| «Сложный список» (`COMPLEX`) | `[{"header":"...","description":"...","level":1}, ...]` | карточки + модальное окно добавления |

Тип списка задаётся системой в `AttributeSpec.listKind` и хранится в
`rpg_character_attributes.list_kind`. Инвентарь всегда простой; в D&D умения,
черты и заклинания — сложные. Старые листы читаются в обоих форматах: тип
выводится из JSON, если `list_kind` не задан.

### Списки: что доступно в просмотре

Изменять лист из режима просмотра нельзя. Два исключения оговорены отдельно:

- **инвентарь** (простой список) — добавление и удаление прямо в просмотре
  (`inventory-add` / `inventory-remove`); выводится отдельным разделом
  `data-block="inventory"`, как блок «Ячейки», вместе с деньгами;
- **сброс ячеек заклинаний** — `POST .../spell-slots-reset`;
- **деньги** (только D&D) — кнопки ± и обмен (`money/change`,
  `money/convert`) в разделе «Инвентарь» (`data-block="money"`); ручного ввода
  суммы в просмотре нет, сумма задаётся формой листа.

Остальные списки правятся только через `POST /characters/{sheetId}/edit`.

### Ограничения кастомных параметров (релиз 3.2.0)

Ограничения задаются при создании параметра в кастомной системе; отдельного
маршрута редактирования нет. Ограничения проверяются и в определении, и при
сохранении значений листа.

| Метод | URL | Описание |
|-------|-----|----------|
| POST | `/rpg/games/{id}/attributes` | `NUMERIC`: `defaultValue`, `minValue`, `maxValue`, `stepValue` (по умолчанию 1); `TEXT`: `optionsText` — значения по одному в строке; общий флаг `manualInputAllowed` (по умолчанию `false`) |

Те же ограничения задаются автором системы в библиотеке (`/rpg/systems/new`,
`/rpg/systems/{id}/edit`) в блоке «Состав параметров листа» и переносятся в
параметры листа при создании игры на этой системе:

| Поле формы | Смысл |
|------------|-------|
| `templateAttributes[i].defaultValue`, `.minValue`, `.maxValue`, `.stepValue` | числовой параметр |
| `templateAttributes[i].defaultText`, `.optionsText` | текстовый параметр (варианты по одному в строке) |
| `templateAttributes[i].manualInputAllowed` | флаг ручного ввода (по умолчанию `false`) |

Поведение в форме листа:

| Ручной ввод | Варианты | Что показывается |
|-------------|----------|------------------|
| есть | нет | обычное текстовое поле |
| есть | есть | список вариантов и пункт «Другое», раскрывающий текстовое поле |
| нет | есть | список вариантов без «Другого» |
| нет | нет | создание параметра отклоняется (400) |

Для `NUMERIC` без ручного ввода поле заполняется только стрелками с шагом
`stepValue`; `minValue` и `maxValue` ограничивают ввод и значение. Значение
вне границ, а для текстового поля при запрещённом ручном вводе — значение не из
списка, отклоняются (400) и не сохраняются. Числовое значение по умолчанию
применяется к новому листу. Поля параметров кастомной системы вынесены в
`rpg_custom_attributes`: `default_value`, `default_text`, `min_value`,
`max_value`, `step_value`, `options_text`, `manual_input_allowed`.

## Уведомления ролевых игр (релиз 3.2.0)

Новых маршрутов нет: события ролевых игр порождают те же существующие POSTы.
Уведомления появляются в общем списке `/notifications`.

| Событие | Кому | Тип уведомления | Ссылка |
|---------|------|-----------------|--------|
| Создана игра | подписчики ведущего | `RPG_GAME_CREATED` | `/rpg/games/{id}` |
| Подана заявка | ведущий | `RPG_APPLICATION_SUBMITTED` | `/rpg/games/{id}` |
| Заявка отозвана | ведущий | `RPG_APPLICATION_WITHDRAWN` | `/rpg/games/{id}` |
| Заявка принята | игрок | `RPG_APPLICATION_ACCEPTED` | `/rpg/games/{id}` |
| Заявка отклонена | игрок | `RPG_APPLICATION_REJECTED` | `/rpg/games/{id}` |
| Игрок покинул игру | ведущий | `RPG_GAME_PLAYER_LEFT` | `/rpg/games/{id}` |
| Игрок удалён ведущим | игрок | `RPG_GAME_PLAYER_REMOVED` | `/rpg/games/{id}` |
| Игра сменила статус | принятые игроки | `RPG_GAME_STATUS_CHANGED` | `/rpg/games/{id}` |
| Новый пост в комнате | участники, которым комната доступна, и ведущий (если пишет игрок) | `RPG_ROOM_POST` | `/rpg/games/{id}/rooms/{roomId}` |

Автор действия уведомления не получает. События публикует модуль `rpg`,
уведомления создаёт слушатель в `forum`, поэтому зависимость `rpg → forum`
отсутствует.

## Библиотека ролевых систем (релиз 3.1.0)

Кнопка «Системы» на странице `/rpg/games` показывается только авторизованным.

Система публикуется в общую библиотеку с указанием названия, описания, видимости
и **состава параметров листа** (типовая анкета). Для параметра типа `LIST`
автор выбирает вид списка: `SIMPLE` или `COMPLEX`. При создании игры на этой
системе анкета переносится в `rpg_custom_attributes`, поэтому ведущему не нужно
заполнять параметры вручную (уже созданные параметры игры не перезаписываются).

| Метод | URL | Описание | Вид |
|-------|-----|----------|-----|
| GET | `/rpg/systems?search=&page=` | Библиотека систем: блоки «Мои системы» и «Публичные системы», каждый со своей пагинацией по 10 строк; `search` — по названию, `page` — номер страницы (с нуля) | `rpg/systems-list` |
