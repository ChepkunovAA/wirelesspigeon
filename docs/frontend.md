# Фронтенд

Фронтенд — **серверный рендеринг** на стороне Spring MVC. JS/CSS
подключается через CDN, интерактивность — **Alpine.js** прямо в HTML.

## 1. Стек

| Технология | Назначение |
|------------|-----------|
| Thymeleaf 3.1 | Шаблоны, выражения `th:*` |
| Bootstrap 5.3 + Bootstrap Icons | Стили, сетка, иконки, компоненты |
| Alpine.js 3.13 | Модалки, раскрытие, аякс-реакции (`x-data`, `x-show`, `x-on`, `@click`) |
| Встроенный CSS | `webapp/src/main/resources/static/css/app.css` |

## 2. Расположение

- Шаблоны: `webapp/src/main/resources/templates/`
  - `home.html`, `profile.html`, `profile-user.html`, `settings.html`, `keys.html`
  - `auth/login.html`, `auth/register.html`
  - `forum/` (list, create, topic, post-фрагмент, attachments-фрагмент)
  - `notifications.html`
  - `cinema/`, `gifts/`, `users/`, `admin/`
  - `fragments/nav.html` — общая навигация
- Статика: `webapp/src/main/resources/static/` (`css/`, `assets/`)
- `thymeleaf.cache: false` в dev — шаблоны перечитываются без рестарта.

## 3. Соглашения

- Все URL в шаблонах **относительные** — `@{...}` / `th:href` (это
  критично для работы через HTTPS-прокси без mixed-content, см.
  `https-migration.md`).
- Формы, изменяющие данные, — `method="post"` с `_csrf` (Thymeleaf
  добавляет автоматически в `th:action`-формах):
  ```html
  <form th:action="@{/forum/topic/{id}/comment(id=${topic.id})}" method="post">
      <input type="hidden" th:name="${_csrf.parameterName}" th:value="${_csrf.token}"/>
      ...
  ```
- Русская локаль UI; бейджи/чипы типов тредов используют **отображаемые**
  лейблы (OPEN и GUEST → «Открытый», GUEST дополнительно — «доступен гостям»,
  см. `security.md`).
- `fragments/nav.html` — единая навигация, подставляется во всех
  страницах через `th:replace`.

## 4. Alpine.js — примеры применения

**Сворачивание поддерева комментариев** (topic.html):
```html
<div x-data="{open: window.__subtreeOpen(topicId, postId)}"
     data-topic-id data-post-id>
    <button @click="open = !open; window.__setSubtree(...)">
        <template x-if="!open"><span>Раскрыть N комментариев</span></template>
        <template x-if="open"><span>Свернуть</span></template>
    </button>
    <div x-show="open" x-cloak> ... поддерево ... </div>
</div>
```
Состояние раскрытия сохраняется через `window.__subtreeOpen/__setSubtree`
(в `sessionStorage`/`localStorage`), чтобы не сбрасываться при навигации.

**Реакции (лайки/дизлайки) без перезагрузки** (post/фрагмент):
```html
<span x-data="react()" data-liked data-likes data-disliked data-dislikes
      data-own data-like-url data-unlike-url data-dislike-url data-undislike-url>
    <button :class="liked ? 'btn-primary' : 'btn-outline-primary'"
            :disabled="own" @click="toggleLike()">
        <i class="bi" :class="liked ? 'bi-hand-thumbs-up-fill' : 'bi-hand-thumbs-up'"></i>
        <span x-text="likes">0</span>
    </button>
    ...
</span>
```

**Показ/скрытие элементов** — `sec:authorize` для серверной проверки ролей
и `x-show`/`x-if` для клиентской.

## 5. Структура страницы треда (forum/topic.html)

1. Карточка **стартового поста (OP)**: заголовок, автор, дата, содержание,
   вложения, лайки/дизлайки треда.
2. Комментарии:
   - без продолжений — хронологическая лента;
   - с продолжениями — свёрнутое поддерево OP («Раскрыть N комментариев»)
     + посты-продолжения + обычные комментарии **ниже** (багфикс 6.1).
3. Пагинация `/forum/topic/{id}?page=N`.
4. Форма «Оставить комментарий» (multipart — поддержка файлов).

## 6. Лейблы типов тредов (чипы/бейджи/options)

Используются единые отображаемые названия:
- PUBLIC → «Публичный»
- OPEN → «Открытый»
- GUEST → «Открытый» + «доступен гостям»
- CLOSED → «Закрытый»

Эти лейблы используются в `list.html` (чипы/бейджи), `topic.html` (бейджи),
`create.html` (options формы + чекбокс «доступен гостям»), `settings.html`
(options настройки), и в списке «Скрывать открытые треды, доступные гостям»
(гостевые = «Открытый» + «доступен гостям»). Вкладка «Открытые» в списке
форума фильтрует OPEN и GUEST вместе.

## 6.2. Отображение времени

Все времена приложения — `LocalDateTime` **wall-clock UTC** (конвенция
хранения, детерминируется `app.time-zone: UTC` в `application.yml`,
`webapp/.../config/TimeZoneConfig.java`). Сервер рендерит UTC-фоллбэк через
фрагмент `fragments/time-format.html` (`time` ↔ `clock(ldt, pattern)`), который
выдаёт `<time data-utc="…Z">` с текстом по `#temporals.format`. Скрипт
`static/js/time-format.js` (подключён в `fragments/nav.html`) переводит каждый
`<time data-utc>` в **таймзону браузера** пользователя; при
`data-utc-mode="date"` — только дата. Форматы: «дата+время» `dd.MM.yyyy HH:mm`
(посты, комментарии, токены, уведомления, участники), «только дата»
`dd.MM.yyyy` (карточка поста на главной, дата просмотра в кино, дата
регистрации). Для динамически подгружаемого контента вызывается
`window.corpsmanTimes()`.

При изменении разметки проверяйте страницу на узком экране (mobile-first).

## 9. RPG: списки листа и ячейки заклинаний (релиз 3.1.0)

### Типы списков

| Тип | Где задаётся | Правка в интерфейсе |
|-----|--------------|--------------------|
| «Простой список» (`SIMPLE`) | `AttributeSpec.listKind`, `rpg_character_attributes.list_kind` | `<textarea>`, по одному элементу в строке |
| «Сложный список» (`COMPLEX`) | там же | карточки + модальное окно (заголовок/описание/уровень) |

Инвентарь всегда `SIMPLE`; в D&D умения, черты и заклинания — `COMPLEX`.
Хранение: `["Факел"]` против `[{"header":"...","description":"...","level":1}]`.
Старые листы читаются в обоих форматах, тип выводится из JSON при `list_kind = null`.

### Просмотр листа — только чтение

- Списки (простые и сложные) показываются без кнопок правки и модалок.
- Исключения, оговорённые отдельно: **инвентарь** (добавление/удаление) и
  **сброс ячеек заклинаний** (`POST spell-slots-reset`).
- Заклинания группируются по уровню: `spellGroups` (`SpellGroupDto` → `level`
  + `items`), уровни по возрастанию, у элемента сохранён абсолютный `index`.

### Форма редактирования

- **Разделов листа три**: «Параметры», «Инвентарь» (`data-block="inventory"`)
  и «Ячейки». Деньги лежат внутри инвентаря отдельным подзаголовком
  (`data-block="money"`), в общем списке параметров их нет.
- **Пробный лист системы** (`/rpg/systems/{id}/character`) заполняет поля
  формы значениями по умолчанию: показ (`sheet.attributes`) и форма
  (`sheetForm`) собираются отдельно, и без переноса значения в форму стрелки
  числового поля не работали.
- **Текстовое поле с вариантами и ручным вводом** (кастомные параметры) рисуется
  так же, как «Класс» и «Раса» в D&D: список вариантов плюс пункт «Другое»,
  который раскрывает текстовое поле. Значение по умолчанию подставляется в
  поле, если поле пустое.
- **Шаг числового поля не подгоняется под границу.** Если значение после
  шага вышло за диапазон, оно не меняется (нижняя граница 10, шаг 3, значение
  11, шаг вниз — остаётся 11). Исключение — уровень D&D: он не может быть
  ниже 1.
- **Конкурентные правки денег** — атомарные UPDATE (`addMoney`, `spendMoney`),
  а не «прочитал, прибавил, записал» через JPA: иначе одновременные кнопки дают
  конфликт версии строки и ответ 500.
- **Инлайновый JS и `th:inline="javascript"`.** Thymeleaf вырезает
  `/*[[выражение]]*/` вместе с окружающим кодом, поэтому в одной строке
  допустимо только одно такое выражение, иначе получается синтаксическая
  ошибка и страница теряет весь скрипт. Рабочая форма —
  `const X = /*[[...]]*/ значение;`. Если на странице осталось `/*[[`, значит
  скрипт не разобрался: это проверяет `renderedPagesHaveNoUnprocessedInlineJs`.
- **Просмотр листа: деньги без перезагрузки.** Формы `money/change` и
  `money/convert` помечены `data-money-change` / `data-money-convert-form`, а
  значения разрядов выводятся в `[data-money-value="<разряд>"]`. Один
  делегированный слушатель `submit` на блоке `[data-block="money"]` делает
  `fetch` и подменяет `innerHTML` блока ответом сервера. Делегирование (а не
  слушатель на каждой форме) обязательно: подмена `innerHTML` уничтожает
  формы вместе с их слушателями. Без JS формы работают обычной отправкой.
- **Деньги** — строки разрядов (`data-money-row`): подпись, кнопки ±
  (`data-money-step`, ширина у всех разрядов одинаковая — `.money-step`),
  значение, сокращение. Между строками разрядов стоит блок обмена
  (`data-money-convert-row`) с кнопками «→ 10 <младший>» и «← 1 <свой>»; у
  младшего разряда блока нет. На странице просмотра полей ручного ввода нет
  (маршрут `money/set` удалён), в форме редактирования сумма задаётся сразу по
  всем разрядам.
- **Деньги** (только D&D): поле `attributes[i].numericValue` с `min=0`,
  стрелки на единицу (`data-money-step`) и обмен с младшим разрядом
  (`data-money-convert=up|down`, курс 1:10, одно нажатие — один обмен).
  Обмен выполняется в браузере и сохраняется вместе с листом; у меди кнопок
  обмена нет. Разряды приходят из `CharacterSheetService.renderForEdit`
  (`moneyEdits`: индекс параметра, значение, минимум, ключ младшего разряда).
- **Простой список** (инвентарь) — карточки + поле ввода + кнопка «+»
  (`data-simple-cards` / `data-simple-input` / `data-simple-add`), значение
  хранится в `attributes[i].listText` (по строке на элемент).
- **Сложный список** — поля ввода нет вообще: только кнопка «Добавить» и
  модалка. Для `spells` в модалке есть числовое поле «Уровень».
- **Сложный список** — скрытое поле `attributes[i].listJson`, карточки рисует
  JS из `RPG_ATTRS`. Модалка `list-add-modal-{key}` — **без `<form>`** и с
  кнопкой `type="button"`: подтверждение обрабатывает JS. Раньше модалка была
  отдельной формой, и её submit перезагружал страницу, теряя список.
- Тип списка передаётся скрытым полем `attributes[i].listKind`.
- Комментарии внутри циклов шаблона оформляются как `<!--/* … */-->`: обычный
  `<!-- … -->` попадает в HTML и его текст (например «Инвентарь») находится
  раньше нужного блока.

### Ячейки заклинаний

- Атрибуты `spell_slot_max:N` / `spell_slot_current:N` — отдельный блок
  «Ячейки», в общий список параметров не попадают (`AttributeViewDto.spellSlot`).
- **Все 9 уровней на отдельных строках** в режиме редактирования
  (`buildSpellSlotEdits`), иначе нельзя задать ячейки нового уровня.
- Счётчик: две кнопки `+/-` (`.btn-slot-step`, `data-slot-step`, `data-slot-level`)
  и два `input[type=number][min=0]` через `/`. `current` не может превышать `max`,
  отрицательные значения запрещены, «Заполнить» (`#spell-slots-fill`) ставит
  `current = max` по всем уровням.
- В просмотре видны только непустые уровни, строкой `текущее / максимальное`.

### Библиотека систем

- Форма публикации содержит название, описание, видимость и **состав параметров
  листа**: строки с названием, типом, видом списка (только для `LIST`) и
  ограничениями значения. Добавление и удаление строк — на клиенте. Поля
  каждой строки помечены `data-attr-*`/`data-new-*`, и `assignNames()`
  выставляет им `name="templateAttributes[i].поле"` при каждой перенумерации —
  без этого добавленные параметры не уходят на сервер.
- Ограничения строки показываются по типу параметра: `numeric-constraints`
  (по умолчанию, нижняя и верхняя границы, шаг) для числового,
  `text-constraints` (по умолчанию и варианты по одному в строке) для
  текстового, флаг «Разрешить ручной ввод» — для обоих. Варианты в форме —
  одна строка `templateAttributes[i].optionsText`, в JSON системы хранится
  список `options` (`SystemAttributeDto.setOptionsText` привязывает одно к
  другому).
- Страница системы показывает состав параметров таблицей (название, тип, вид
  списка) и, для автора, кнопки «Редактировать», «Форк», «Удалить» и
  «Создать игру на этой системе» со ссылкой
  `/rpg/games/new?system=CUSTOM&customSystemId={id}`.
- Форк системы — не мгновенное копирование, а переход на форму создания:
  пиктограмма ведёт на `/rpg/systems/new?forkFrom={id}`, где уже стоят название
  с суффиксом «(форк)» (при совпадении — «(форк) 1», «(форк) 2»…), описание и
  состав параметров исходной системы; видимость приватная. Копия появляется
  только после отправки формы, исходная система не меняется.
- Кнопка «Форк» доступна **любому** вошедшему пользователю и поэтому стоит вне
  блока автора (`th:if="${currentUserId != null}"`). Кнопки «Редактировать» и
  «Удалить» — только автору: в списке через `authorIds` из модели, на странице
  системы через `isAuthor`. Поэтому у чужой публичной системы видны «Просмотр»
  и «Форк», а у собственной — все четыре. Сравнение с
  `#authentication.principal.id` в шаблоне ломает страницу для гостя — у
  анонимного `principal` нет `id`.
- Бейдж версии системы («vN») и колонка `rpg_system_definitions.system_version`
  удалены (Liquibase `3.1.0-07`): версия выставлялась в 1 при создании и больше
  не менялась, то есть показывала одно и то же значение.
- `HttpRequestMethodNotSupportedException` обрабатывается как 405, а не 500:
  GET на POST-эндпоинт больше не даёт внутреннюю ошибку.
- Страница игр (`rpg/games.html`) содержит кнопку «Системы» — переход в
  библиотеку; она скрыта от неавторизованных (`th:if="${canCreate}"`).
- Список игр разбит на два раздела с собственной пагинацией: «Мои игры»
  (`data-section="mine"`, `?myPage=`) и «Все игры» (`data-section="others"`,
  `?page=`). В «Моих» только незавершённые игры, которые зритель ведёт либо в
  чём участвует; завершённые остаются в общем списке, поэтому своя игра в
  «Моих» и в общем списке не повторяется, а раздел «Мои игры» не сдвигается
  при переходе по страницам общего списка.
- Фон строки по статусу задаётся классами `game-row--recruiting`,
  `game-row--active`, `game-row--closed` и переменными темы `--app-game-*`:
  в светлой теме светлые оттенки, в тёмной — тёмные зелёный и синий, у
  завершённых — оттенок карточки (`--app-surface`). Классы задают **`--bs-table-bg`**,
  а не `background-color`: Bootstrap 5.3 красит фон ячеек таблицы
  (`.table > :not(caption) > * > *`) через `--bs-table-bg`, поэтому обычный
  фон строки закрашивается ячейками и все строки выглядят одинаковыми.
- Блоки формы вне общего списка параметров (ячейки, деньги, инвентарь) обязаны
  отдавать `<input type="hidden" th:field="*{attributes[i].key}">`: сервер
  сопоставляет значения формы по ключу, и запись без ключа молча
  отбрасывается — значение не сохраняется, хотя браузер отправил его.
- В списке систем обратная ссылка ведёт на игры и подписана «К играм».
- Форма создания игры принимает `?system=CUSTOM&customSystemId={id}` и
  предвыбирает систему (и конкретную систему из библиотеки).
- На странице игры кнопка «Редактировать лист» ведёт на
  `/characters/{sheetId}/edit`, если лист уже есть (`GameDetailDto.viewerSheetId`),
  и только иначе — на форму подачи заявки.
- Форма создания/редактирования игры: при выборе системы `CUSTOM` появляется
  блок «Система из библиотеки» (`#custom-system-block`, показывается обычным
  обработчиком `change`, без Alpine). Список берётся из
  `libraryService.getAvailableSystems(uid)` — и публичные, и свои приватные;
  он не теряется при ошибке валидации.
- На странице системы — кнопка «Открыть режим создания»
  (`GET /rpg/systems/{id}/character`): форма листа в режиме `previewMode` с
  составом параметров из анкеты системы. Кнопки отправки нет вовсе, а форма
  помечена `onsubmit="return false"` — иначе Enter в поле отправил бы POST на
  GET-адрес и получил 405.
- У ведущего на `/rpg/games/{id}/attributes` параметр типа «Список» создаётся с
  выбором вида (простой/сложный) — вид показывается бейджем в таблице.
- Поле формы называется `published`, а не `isPublic`: Thymeleaf не биндит
  примитивный boolean с префиксом `is` (`SpringInputCheckboxFieldTagProcessor`).
- Переключатель «Игроки видят все параметры листа друг друга» на форме игры
  имеет ту же проблему, что и видимость системы: поле `GameForm.attributesVisible`
  по умолчанию `true`, поэтому перед галочкой стоит скрытое
  `<input type="hidden" name="attributesVisible" value="false"/>`.
- Перед переключателем «Публичная система» стоит скрытое
  `<input type="hidden" name="published" value="false"/>`: снятая галочка не
  отправляется вовсе, а значение по умолчанию в форме — `true`, поэтому без
  скрытого поля снятая галочка всё равно сохраняла публичную систему.
- `th:class` заменяет атрибут `class` целиком, а `th:classappend` дополняет
  его. Условный цвет бейджа («Публичная»/«Приватная») задаётся только через
  `th:classappend`, иначе теряется базовый класс `badge` вместе со скруглениями
  и жирным начертанием.
- Скрытое поле в Thymeleaf пишется статически: `th:name="*{prop}"` вместе с
  литеральным `value="false"` даёт `name="false"`.
- Поля «Порядок» в интерфейсе кастомной системы нет: автор задаёт только
  последовательность параметров, а позиции для разделов листа (`0, 10, 20, …`)
  проставляет `GameSystemLibraryService.writeTemplateAttributes` по номеру строки,
  игнорируя присланное значение. Позиция определяет раздел листа: параметр
  показывается как `400 + position` (`CustomCharacterSystem.toSpec`), а
  `CharacterSheetService.sectionHeader` режет лист на «Основное» / «Характеристики»
  / «Спасброски» / «Навыки» / «Параметры» (позиция < 500) и отдельные блоки
  (≥ 500). Стрелки ведущего на `/rpg/games/{id}/attributes` переписывают позиции
  в 0, 1, 2… — авторские значения не сохраняются.

### Цвета карточек

Текст карточек, таблиц и списков задаётся переменными темы, а не
захардкоженными оттенками: `--app-card-text` (основной) и `--app-card-muted`
(описания, статусы, подписи). В тёмной теме они светлее фона карточки
(`--app-surface`), в светлой — темнее. Правило проверяется тестом
`DesignStyleIntegrationTest`: в шаблонах листа не должно быть литералов
`color: #495057` / `color: #6c757d`, иначе описание элемента или шеврон
окажутся нечитаемыми в тёмной теме.

### Прочие правила отображения

- Пустые текстовые значения (`TEXT`) выводятся как `—`, а не скрываются:
  блок «Основное» не разъезжается, когда класс/раса/предыстория не заданы.

### Подтип текстового поля и проверка формы листа

- Подтип текстового поля выбирается отдельным списком («Свободный» /
  «Выбираемый»). Список вариантов и флаг ручного ввода показываются только у
  выбираемого; у свободного список очищается, а ручной ввод включается
  принудительно — иначе поле нечем заполнить.
- Формы с подтипом используют маркеры `data-attr-mode-select` (строка
  анкеты) и `data-attr-text-mode`; у каждой строки своё состояние, поэтому
  переключение подтипа в одной строке не влияет на остальные.
- Проверка перед сохранением (`validateSheet`) живёт в `apply.html` и
  отвечает за три случая, которые раньше доходили до сервера и давали 400:
  число вне границ, значение не из списка вариантов, отрицательное количество
  монет. Кнопка сохранения (`#sheet-submit`) блокируется, у поля появляется
  сообщение в `[data-validation-error]`.
- Правило общее для всех полей листа, но проверяются только те, где сервер
  действительно отвечает 400: свободный текст без значения сервер принимает,
  поэтому клиент его не блокирует.

### Поле «Вид» и предупреждение о значении по умолчанию

- Заголовок «Подтип» переименован в «Вид»; значение сохраняется в составе
  системы (поле `textMode`), а не восстанавливается из наличия списка
  вариантов.
- Маркер предупреждения `[data-default-warning]` показывается у строки, у
  которой вид «По выбору», а значения по умолчанию нет в списке вариантов.
  Он же работает в анкете игры (`#attr-default-warning`). При сохранении
  значение добавляется в список на сервере.
- Разбор списка вариантов — `split(/\r?\n/)`. **Не используйте `split(/\R/)`
  в JavaScript:** без флага `u` это регулярка по букве `R` (Annex B), и список
  не разбивается на строки. В Java `split("\\R")` корректно.
