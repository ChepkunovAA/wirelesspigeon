### Пункты постановки

1. **Заглушка удаления владельцем/админом без потомков.** Ранее заглушка
   на месте удалённого комментария показывалась только если у него были
   ответы/потомки (`subtreeSize > 0`) или `deletedByAdmin`. Уточнено:
   при удалении владельцем треда или администратором заглушка
   («Удалено владельцем треда» / «Удалено администратором») показывается
   всегда, даже если потомков нет. В шаблонах (`topic.html`, `post.html`)
   в условия рендера дерева добавлен `deletedByOwner`; в `post.html`
   добавлен отдельный текст заглушки для владельца треда.
2. **Баг: число комментариев после удаления.** Счётчики считали и
   удалённые (мягко удалённые) посты. Исправлено:
   - `ForumService.subtreeSize` — не учитывает `deleted` (счётчик «Раскрыть N»);
   - `ForumPostRepository.countByTopicIdIn` — фильтр `p.deleted = false`
     (счётчик «N комментариев» на карточках треда на главной/в списке);
   - добавлено `TopicDetailDto.nonDeletedCount` — количество неудалённых
     комментариев треда (заголовок «Комментарии (N)» на странице треда).
   Следствие: полностью удалённое авторизованным автором поддерево
   (без выживших комментариев) полностью скрывается.
3. **Багфиксы интерфейса (navbar / уведомления):**
   - **3.1** Неавторизованный пользователь не видел кнопку «Форум» — весь
     левый блок навигации (`fragments/nav.html`) был обёрнут в
     `sec:authorize="isAuthenticated()"`, хотя `/forum` — `permitAll`
     (аноним видит PUBLIC треды). Снят authorize с `<ul>`, «Форум» теперь
     доступен анониму; «Кино»/«Ключи» скрыты по роли, «Подарки»/
     «Участники» — требуют авторизации (соответствует `SecurityConfig`).
   - **3.2** Уведомления некликабельны — каждая запись в
     `notifications.html` была `<form>` без submit-кнопки, поэтому форма не
     отправлялась по клику. Добавлен `onclick="this.submit()"`,
     `cursor: pointer` и скрытая submit-кнопка — запись кликабельна и
     переходит по ссылке (`/notifications/{id}/read?to=...`).
   - **3.3** Кнопка «Выйти» не выровнена по уровню navbar — правому `<ul>`
     добавлен `align-items-lg-center`, `<li>` — `d-flex align-items-center`,
     форме logout — `mb-0` (вертикальное выравнивание по остальным пунктам).

### Пункты постановки

1. **Доступ анонимов к форуму.** `GET /forum` и `GET /forum/topic/{id}` —
   `permitAll`; аноним видит только `PUBLIC` треды; запись анониму
   недоступна (POST → 302 на `/login`, без CSRF → 403).
2. **Чистая главная.** Убраны плитки «Форум», «Вишлисты», «Кинотеатр»;
   кино-блок («Следующий фильм») виден только `RESIDENT+` (для гостя и
   анонима скрыт).
3. **Удаление комментариев владельцем треда.** Миграция
   `22-deleted-by-owner`; заглушка «Удалено владельцем треда»
   (`ForumPost.deletedByOwner`).
4. **«Лучший пост» и «Последний пост» на главной.**
   - Оба блока в одинаковой стилистике (фрагмент `home-post`), видны всем.
   - Под «постом» понимается стартовый пост (OP) или пост-продолжение
     (`is_op = true OR is_continuation = true`); НЕ обычные комментарии.
     Оба типа тредов бизнес-логически эквивалентны и участвуют в подборках.
   - «Последний» — по `created_at DESC`; «Лучший» — `likes - dislikes`.
   - Посты выбираются **персонально** по роли и настройкам видимости:
     аноним — только `PUBLIC`; `GUEST` — без `OPEN`; настройки
     `showPublicPosts`/`hideGuestThreads`; `CLOSED` — владелец/`MASTER`/whitelist.
   - Логика «Обсуждаемого поста недели» удалена (упрощение постановки).
5. **Переклассификация тредов.** Переименованы отображаемые лейблы:
   GUEST → «Открытый», OPEN → «Внутренний». Гости получают возможность
   создавать **закрытые** треды (SELECT с GUEST и CLOSED).
6. **Багфиксы:**
   - **6.1** Порядок комментариев: новые комментарии отображались выше
     поста-продолжения — исправлено (в `topic.html` обычные комментарии
     рендерятся ниже секции продолжений).
   - **6.2** Уведомления не становились прочитанными — исправлено
     (`markRead(id, userId)`, `POST /notifications/{id}/read`).
   - **6.3** При создании закрытого поста whitelist не настраивался —
     исправлено (select для гостей с GUEST/CLOSED, `x-init` установки
     `vis` из select).
   - **6.4** Кнопки раскрытия поддерева выровнены (одинаковые классы
     `btn btn-link btn-sm p-0 ...` у стартового поста и поста-продолжения).

### П.6 (готово): админы не видят закрытые треды без белого списка
Раньше `MASTER` обходил CLOSED-фильтр и видел любые закрытые треды. Теперь
админ, как и любой участник, видит закрытый тред только если он его автор
или добавлен в белый список:
- `ForumTopicRepository.search` — убрано `:adminMode = true` из CLOSED-условия
  (сигнатура: параметр `adminMode` удалён);
- `ForumService.isVisible` — убрано `ctx.adminMode()` для CLOSED;
- `ForumService.canViewClosed` — убрано `isAdmin ||` (параметр `isAdmin` удалён);
- `ViewerContext` — поле `adminMode` удалено как неиспользуемое.

Запись/реакции в закрытом треде и раньше требовали whitelist/авторство — не менялось.

### П.3 (готово): отображаемое время = системное время
Все времена хранятся и выводятся как `LocalDateTime` в локальном времени JVM
(серверное/системное время), рендерятся `#temporals.format` без сдвига. Добавлена
`TimeZoneConfig` в webapp:
- таймзона JVM по умолчанию делается явной через свойство `app.time-zone`
  (пустое значение — остаётся системная таймзона хоста; можно задать, например,
  `UTC`, `Europe/Moscow`);
- бин `Clock` (`systemClock()`) — системные часы приложения для детерминированного
  получения текущего момента.
Отображаемое время всегда равно системному времени сервера приложения.
Тест: `TimeZoneConfigTest`.

### П.4 (готово): тёмная тема (кнопка слева внизу)
Глобальная тёмная тема на всех страницах (`Bootstrap 5.3` via CSS-переменные +
`data-bs-theme` на `<html>`):
- **Ассеты**: из `dark_asset.jpg` (тёмная версия эмблемы, та же информация, что
  в `logo.png`) сгенерированы `assets/dark-asset.png` (тёмный логотип) и
  `assets/mask-tile-dark.png` (фоновая плитка-«шахмата» 2×2, тот же подход, что
  и светлая `mask-tile.png`). В тёмной теме логотип и фон используют `dark-asset`
  вместо стандартных;
- **CSS** (`app.css`): ключевые цвета приложения переведены на CSS-переменные
  (`--app-bg`, `--app-surface`, `--app-post-op-bg`, ...); блок тёмной темы под
  `html[data-bs-theme="dark"]` инвертирует только цвета приложения
  (заглавный пост, card-header, закрытые треды, лейблы, светлые поверхности
  `bg-white`/`text-dark`/`border-light`) — user-content (аватарки, вложения,
  фото постов) **не** инвертируется;
- **Тумблер**: `position:fixed; bottom; left`, в `fragments/nav` (покрывает все
  страницы с nav) + отдельно в `auth/login.html`, `auth/register.html`,
  `error.html` (страницам без nav) — через общий `static/js/theme.js`;
- **theme.js**: читает выбор из `localStorage` (`corpsman-theme`), по умолчанию
  уважает `prefers-color-scheme`; переключение мгновенно меняет `data-bs-theme`
  на `<html>` и сохраняется между страницами.
Тесты: `DesignStyleIntegrationTest` (ассеты/тумблер/скрипт/блок темы в app.css).

### П.5 (готово): переработка открытых и гостевых тредов

### Багфиксы (приёмка релиза)
Исправлено по результатам приёмки деплоя 2.3.0:
- **Чекбокс «доступен гостям» не виден в форме создания треда.** В `x-data`
  Alpine потерялись фигурные скобки: `x-data="vis: 'OPEN'"` — невалидный
  объектный литерал, `vis` оставался `undefined`, и `x-show="vis === 'OPEN'"`
  навсегда скрывал чекбокс (и dropdown белого списка). Возвращены скобки:
  `x-data="{vis: '${topic.visibility}'}"`.
- **В тёмной теме не менялся фон.** Bootstrap задаёт `.bg-light {
  background-color: ... !important }`, а наш оверрайд `html[data-bs-theme]
  body` был без `!important` и проигрывал. Добавлен `!important`.
- **Тумблер темы работал только светлая→тёмная.** Если атрибут
  `data-bs-theme` на момент клика отсутствует, `next` всегда вычислялся как
  `dark`. Теперь текущая тема берётся из атрибута, а при его отсутствии — из
  хранилища: `getAttribute('data-bs-theme') || currentTheme()`.
- **Переключатель мог «не работать» на отдельной странице.** `theme.js`
  дополнительно защищён: идемпотентность (`window.__corpsmanThemeInit`) —
  повторное подключение скрипта не навешивает дубль-слушатели, из-за которых
  один клик переключал тему дважды и выглядел как «ничего не происходит»;
  слушатель клика вешается и при уже отработавшем `DOMContentLoaded`
  (`document.readyState === 'loading'` → иначе `init()` сразу).
- **Маркер «доступен гостям» виден всем ролям.** По принципу «вне зависимости
  от роли не должно быть намёков на скрытый функционал» бейдж «доступен
  гостям» теперь рендерится только для `RESIDENT`/`MASTER`
  (`sec:authorize="hasAnyRole('RESIDENT','MASTER')"` в `list.html` и
  `topic.html`); гости по-прежнему видят сами гостевые треды и лейбл
  «Открытый».
- **Error 500 при открытии треда неавторизованным.** `topicDetail` вызывал
  `settingsService.getByUserId(null)` и `isSubscribedToTopic(null, ...)` для
  анонимов → `IllegalArgumentException: The given id must not be null`.
  Загруженный один раз `viewerId` = `SecurityUtils.currentUserId()`; настройки
  и подписка читаются только при `viewerId != null` (анониму — дефолт).
- **Error 500 при прямом открытии формы создания треда неавторизованным.**
  `showCreateForm` аналогично звал `settingsService.getByUserId(null)`.
  Теперь, если `viewer == null`, форма отдаёт редирект на `/login`
  (кнопка создания в UI у анонима всё равно не показывается).
- **Тумблер темы «не кликабелен», если контент страницы доходит до его угла.**
  Это не JS: `.navbar`, `main` и `footer` имели общий `z-index: 1`. `<nav>`
  создаёт stacking context (внутри него `position:fixed` тумблер с
  `z-index:1050`), а `main` с тем же `z-index: 1` и позже в DOM перекрывал
  поддерево nav — карточки тредов/поста «съедали» клики по кнопке
  (`document.elementFromPoint` в её области возвращал элемент контента).
  Исправление в `app.css`: общий блок `.navbar, main, footer` оставляет только
  `position: relative` (без зип), а `z-index: 1` остаётся лишь у `.navbar` —
  тумблер поверх контента на любом контенте; `main`/`footer` к тому же больше
  не запирают z-index своих потомков (modal, скролл-кнопка).
- Сопутствующее: добавлен `.dockerignore` (контекст docker-сборки падает со
  ~180 МБ до ~0.4 МБ за счёт исключения `*/target`); **Dockerfile переведён на
  упаковку готового jar** без стадии Maven внутри образа (встроенный
  `mvn dependency:go-offline` зависал на ~30 мин на медленном канале до Maven
  Central). Сборка jar выполняется на хосте в тёплый `~/.m2`:
  `mvn clean package -DskipTests`, затем `docker compose up -d --build`
  (образ собирается за секунды, без сети).

Тесты: `DesignStyleIntegrationTest` (asserts `!important` в app.css и фолбэка
в theme.js; `appCssKeepsThemeToggleAbovePageContent` — стек-инвариант: z-index
только у `.navbar`, у `main`/`footer` — нет), `RolesAndGuestThreadsIntegrationTest`
(+2: аноним открывает публичный тред без ошибки; резидент видит маркер на
странице гостевого треда; `anonymousCreateFormRedirectsToLoginWithoutError`;
existing-аксиомы переведены на новое правило «гость не видит маркер»).
Проверка тумблера: jsdom против реального DOM главной страницы и страниц
форума — клик в обе стороны; сценарии «скрипт после DOMContentLoaded» и
«двойная загрузка скрипта»; e2e-скрипт (`e2e-bugs.py`) против развёрнутого
деплоя: пагинация E2E, аноним-create → 302 `/login`.

## Как формируется предстоящий релиз
1. Читаем постановку из `doc/`.
2. Детализируем user stories и критерии приёмки.
3. Unit-тесты сервисов.
4. Реализация по архитектуре (MVCS, события, BaseEntity/BusinessException/MapStruct).
5. Зелёная сборка `mvn test`.
6. `docker compose up -d --build` + E2E по HTTP (curl: логин, ключевые страницы).
7. Коммит в `develop`.

> **Правило git:** работа только в ветке `develop`; каждый спринт/фича
> завершается осмысленным коммитом. Не коммитить в `master`.
