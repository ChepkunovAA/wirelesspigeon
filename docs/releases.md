## Релиз 2.2.1 (багфиксы форума)

Ветка `release/2.2.1` (от `develop`). Слияние в `develop`/`master` — руками
пользователя. Корневой `pom.xml` и `<parent>` всех модулей: `2.2.1`.

### Пункты постановки

1. **Заглушка удаления владельцем/админом без потомков.** Ранее заглушка
   на месте удалённого комментария показывалась только если у него были
   ответы/потомки (`subtreeSize > 0`) или `deletedByAdmin`. Уточнено:
   при удалении владельцем треда или администратором заглушка
   («Удалено владельцем треда» / «Удалено администратором») показывается
   всегда, даже если потомков нет. В шаблонах (`topic.html`, `post.html`)
   в условия рендера дерева добавлен `deletedByOwner`; в `post.html`
   добавлен отдельный текст заглушки для владельца треда.
2. **Баг: число комментариев после удаления.** Счётчики считали и
   удалённые (мягко удалённые) посты. Исправлено:
   - `ForumService.subtreeSize` — не учитывает `deleted` (счётчик «Раскрыть N»);
   - `ForumPostRepository.countByTopicIdIn` — фильтр `p.deleted = false`
     (счётчик «N комментариев» на карточках треда на главной/в списке);
   - добавлено `TopicDetailDto.nonDeletedCount` — количество неудалённых
     комментариев треда (заголовок «Комментарии (N)» на странице треда).
   Следствие: полностью удалённое авторизованным автором поддерево
   (без выживших комментариев) полностью скрывается.
3. **Багфиксы интерфейса (navbar / уведомления):**
   - **3.1** Неавторизованный пользователь не видел кнопку «Форум» — весь
     левый блок навигации (`fragments/nav.html`) был обёрнут в
     `sec:authorize="isAuthenticated()"`, хотя `/forum` — `permitAll`
     (аноним видит PUBLIC треды). Снят authorize с `<ul>`, «Форум» теперь
     доступен анониму; «Кино»/«Ключи» скрыты по роли, «Подарки»/
     «Участники» — требуют авторизации (соответствует `SecurityConfig`).
   - **3.2** Уведомления некликабельны — каждая запись в
     `notifications.html` была `<form>` без submit-кнопки, поэтому форма не
     отправлялась по клику. Добавлен `onclick="this.submit()"`,
     `cursor: pointer` и скрытая submit-кнопка — запись кликабельна и
     переходит по ссылке (`/notifications/{id}/read?to=...`).
   - **3.3** Кнопка «Выйти» не выровнена по уровню navbar — правому `<ul>`
     добавлен `align-items-lg-center`, `<li>` — `d-flex align-items-center`,
     форме logout — `mb-0` (вертикальное выравнивание по остальным пунктам).

## Релиз 2.2.0 (текущий)

### Пункты постановки

1. **Доступ анонимов к форуму.** `GET /forum` и `GET /forum/topic/{id}` —
   `permitAll`; аноним видит только `PUBLIC` треды; запись анониму
   недоступна (POST → 302 на `/login`, без CSRF → 403).
2. **Чистая главная.** Убраны плитки «Форум», «Вишлисты», «Кинотеатр»;
   кино-блок («Следующий фильм») виден только `RESIDENT+` (для гостя и
   анонима скрыт).
3. **Удаление комментариев владельцем треда.** Миграция
   `22-deleted-by-owner`; заглушка «Удалено владельцем треда»
   (`ForumPost.deletedByOwner`).
4. **«Лучший пост» и «Последний пост» на главной.**
   - Оба блока в одинаковой стилистике (фрагмент `home-post`), видны всем.
   - Под «постом» понимается стартовый пост (OP) или пост-продолжение
     (`is_op = true OR is_continuation = true`); НЕ обычные комментарии.
     Оба типа тредов бизнес-логически эквивалентны и участвуют в подборках.
   - «Последний» — по `created_at DESC`; «Лучший» — `likes - dislikes`.
   - Посты выбираются **персонально** по роли и настройкам видимости:
     аноним — только `PUBLIC`; `GUEST` — без `OPEN`; настройки
     `showPublicPosts`/`hideGuestThreads`; `CLOSED` — владелец/`MASTER`/whitelist.
   - Логика «Обсуждаемого поста недели» удалена (упрощение постановки).
5. **Переклассификация тредов.** Переименованы отображаемые лейблы:
   GUEST → «Открытый», OPEN → «Внутренний». Гости получают возможность
   создавать **закрытые** треды (SELECT с GUEST и CLOSED).
6. **Багфиксы:**
   - **6.1** Порядок комментариев: новые комментарии отображались выше
     поста-продолжения — исправлено (в `topic.html` обычные комментарии
     рендерятся ниже секции продолжений).
   - **6.2** Уведомления не становились прочитанными — исправлено
     (`markRead(id, userId)`, `POST /notifications/{id}/read`).
   - **6.3** При создании закрытого поста whitelist не настраивался —
     исправлено (select для гостей с GUEST/CLOSED, `x-init` установки
     `vis` из select).
   - **6.4** Кнопки раскрытия поддерева выровнены (одинаковые классы
     `btn btn-link btn-sm p-0 ...` у стартового поста и поста-продолжения).

## Как формируется предстоящий релиз
1. Читаем постановку из `doc/`.
2. Детализируем user stories и критерии приёмки.
3. Unit-тесты сервисов.
4. Реализация по архитектуре (MVCS, события, BaseEntity/BusinessException/MapStruct).
5. Зелёная сборка `mvn test`.
6. `docker compose up -d --build` + E2E по HTTP (curl: логин, ключевые страницы).
7. Коммит в `develop`.

> **Правило git:** работа только в ветке `develop`; каждый спринт/фича
> завершается осмысленным коммитом. Не коммитить в `master`.
