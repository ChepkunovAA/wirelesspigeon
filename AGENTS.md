# AGENTS.md — правила работы ИИ-агента над проектом Corpsman

## Git
- Работать только в ветке `develop`. НИ ПРИ КАКИХ обстоятельствах не коммитить в `master`.
- Каждый спринт/фича завершается коммитом в `develop`.

## Обязательный workflow (для каждой задачи)
1. **Чтение постановки** — изучить документы в `/home/albert/Project/doc` (architect, sprintN-*).
2. **Детализация/формализация задания** — зафиксировать user stories, критерии приёмки, план.
3. **Написание unit-тестов** — тесты сервисного слоя до реализации (JUnit 5 + Mockito, стиль как в `wishlist/src/test`).
4. **Написание реализации** — код по архитектурным правилам (`doc/architect`): модули Maven, MVCS, BaseEntity/BusinessException/MapStruct, события Spring между модулями.
5. **Прогон unit-тестов** — `mvn test`.
6. **Исправление ошибок** — до зелёной сборки.
7. **Deploy в докер** — `docker compose up -d --build` (Dockerfile и docker-compose.yml существуют).
8. **E2E тестирование** — проверка сценариев по HTTP против поднятого контейнера (curl: логин, регистрация по инвайту, ключевые страницы фичи).
9. **Коммит в develop** — осмысленное сообщение, в коммит только файлы фичи.

## Команды
- Полная сборка с тестами: `mvn clean install`
- Только тесты: `mvn test`
- Деплой: `docker compose up -d --build`
- Логи приложения: `docker compose logs -f app`
