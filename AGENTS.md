# AGENTS.md — правила работы ИИ-агента над проектом Corpsman

## Git
- Работать только в ветке `develop`. НИ ПРИ КАКИХ обстоятельствах не коммитить в `master`.
- Каждый спринт/фича завершается коммитом в `develop`.

## Обязательный workflow (для каждой задачи)
1. **Чтение постановки** — изучить документы в `/home/albert/Project/doc` (architect, sprintN-*).
2. **Детализация/формализация задания** — зафиксировать user stories, критерии приёмки, план.
3. **Написание unit-тестов** — тесты сервисного слоя до реализации (JUnit 5 + Mockito, стиль как в `wishlist/src/test`).
4. **Написание реализации** — код по архитектурным правилам (`doc/architect`): модули Maven, MVCS, BaseEntity/BusinessException/MapStruct, события Spring между модулями.
5. **Прогон unit-тестов** — `mvn test`.
6. **Исправление ошибок** — до зелёной сборки.
7. **Deploy в докер** — `docker compose up -d --build` (Dockerfile и docker-compose.yml существуют).
8. **E2E тестирование** — проверка сценариев по HTTP против поднятого контейнера (curl: логин, регистрация по инвайту, ключевые страницы фичи).
9. **Коммит в develop** — осмысленное сообщение, в коммит только файлы фичи.

## Команды
- Полная сборка с тестами: `mvn clean install`
- Только тесты: `mvn test`
- Деплой: `docker compose up -d --build`
- Логи приложения: `docker compose logs -f app`

## Сборка и тестирование (исследование релиза 2.0.0)

### Граф зависимостей модулей
```
common ← auth ← {cinema, wishlist, forum, users} ← webapp
```
Доменные модули зависят только от common+auth → независимая сборка возможна.

### Измерения (полный mvn test ≈ 342с)
| Способ | Время |
|---|---|
| `mvn test` | 342с |
| `mvn test -T 1C` | 348с (ускорения нет — критический путь webapp) |
| `mvn -q install -DskipTests` (однократно) | 39с |
| после install: `mvn test -pl <module>` | 16–17с на модуль |

webapp = 83% времени (все интеграционные тесты с MVC-шаблонами; перенос
в доменные модули невозможен без выноса шаблонов).

### Правила
1. **Точечная проверка модуля:** разово `mvn -q install -DskipTests`,
   затем `mvn test -pl forum` (и т.п.) — ~15с вместо 5,5 мин.
2. **ЛОВУШКА stale-jar:** `-pl <модуль>` берёт jar зависимостей из ~/.m2.
   После правок common/auth/forum и т.д.: запускать с `-am` ИЛИ переустановить
   артефакты (`mvn -q install -DskipTests`). Симптом: ClassNotFoundException /
   старое поведение при зелёном исходнике.
3. `-T 1C` не использовать — ускорения нет.
4. Избегай дублирования тестов
5. Добейся прохождения unit-тестов до запуска интеграционных тестов из webapp
### HTTPS (релиз 2.0.0 п.1, ветка feature/https, вариант C — Caddy)
- Деплой: caddy терминирует TLS (авто-сертификаты), приложение только :8080 внутри сети
- Домен задаётся `SITE_ADDRESS=домен` (по умолчанию localhost, internal CA)
- Cookie: Secure+HttpOnly+SameSite=Lax включаются переменной COOKIE_SECURE=true
  (в compose включена; локальный dev без прокси остаётся на HTTP с secure=false)
- E2E по https: `curl -sk https://localhost/...` (-k из-за internal CA);
  HTTP автоматически редиректится на HTTPS (308)
- Продление сертификатов не требуется (Caddy сам); для домена — Let's Encrypt автоматом
